# AI tooling (optional)

Contributors use different editors, models, and agent workflows, so none of the
AI instruction files are committed to their live locations. A fresh clone has
none of them — this folder holds the samples, and you link or copy the ones you want.
Same idea as `.env.sample` → `.env`.

Nothing here is required to build, test, or contribute.

## Quick start

Link everything (the maintainer's full setup):

```bash
ln -s docs/ai/AGENTS.md.sample AGENTS.md
ln -s docs/ai/CLAUDE.md.sample CLAUDE.md
ln -s ../docs/ai/copilot-instructions.md.sample .github/copilot-instructions.md

ln -s docs/ai/scripts ai

mkdir -p docs/agents
ln -s ../ai/agents/domain.md.sample docs/agents/domain.md
ln -s ../ai/agents/issue-tracker.md.sample docs/agents/issue-tracker.md
```

Symlinks follow the samples as they change. A copy (`cp` instead of `ln -s`)
is for customizing — it stops getting sample updates, and Conductor workspaces
carry it over as-is instead of linking the branch's sample.

Just Claude Code:

```bash
ln -s docs/ai/CLAUDE.md.sample CLAUDE.md
```

Just Copilot:

```bash
ln -s ../docs/ai/copilot-instructions.md.sample .github/copilot-instructions.md
```

## What each sample does

| Sample | Copy to | Gives you |
|---|---|---|
| `AGENTS.md.sample` | `AGENTS.md` | Architecture reference read by most agent tools (Codex, Cursor, OpenCode, Copilot, Gemini) |
| `CLAUDE.md.sample` | `CLAUDE.md` | Coding rules plus the maintainer's workflow: session recap, reply formatting, PR conventions, `ai/` commands |
| `copilot-instructions.md.sample` | `.github/copilot-instructions.md` | The same coding rules for GitHub Copilot |
| `agents/domain.md.sample` | `docs/agents/domain.md` | Domain-doc config for the `domain-modeling` and `research` skills |
| `agents/issue-tracker.md.sample` | `docs/agents/issue-tracker.md` | Issue-tracker config for `setup-matt-pocock-skills` and `wayfinder` |
| `scripts/` | `ai/` | Task shortcuts: `ai/test`, `ai/lint`, `ai/server`, `ai/console`, and friends |

`docs/agents/` is generated by the `setup-matt-pocock-skills` skill, so running
that skill will write it for you.

## Notes

- **Conductor workspaces.** The Conductor wiring (`.conductor/settings.toml`,
  `bin/conductor-*`) is tracked — Conductor reads `settings.toml` from the
  remote default branch, so it can't be opt-in. Opt in once in your root
  checkout; each new workspace's `bin/conductor-setup` then brings in the same
  files. Unedited copies become symlinks to that branch's samples, so an edit
  to `CLAUDE.md` there lands in `CLAUDE.md.sample` and shows up in the diff.
  Customized copies are copied as-is and stay out of the repo.
- **Personal overlay.** `CLAUDE.local.md` is auto-loaded by Claude Code and is
  the intended home for personal preferences; it is already gitignored. Keep
  repo-wide rules in `CLAUDE.md` and personal habits in `CLAUDE.local.md`.
- **Project skills are tracked.** `.claude/skills/` is committed — Claude Code
  and OpenCode discover it automatically, no opt-in needed. It holds the
  vendored Matt Pocock and Evil Martians packs plus the project's `ai-review`
  skill. Licenses are in `.claude/skills/THIRD_PARTY_NOTICES.md`.
- **Upstream.** The vendored packs come from
  [mattpocock/skills](https://github.com/mattpocock/skills) and
  [evilmartians/agent-skills](https://github.com/evilmartians/agent-skills);
  install them from there if you would rather not use the copy in this repo.
- **Keep samples current.** The sample is the tracked copy, so a rule that only
  lives in your local `CLAUDE.md` is invisible to everyone else. Change a rule in
  the sample here *and* in your live copy of the file — agents are told to do both
  (see the "AI Instruction Files" section of `CLAUDE.md.sample`).
