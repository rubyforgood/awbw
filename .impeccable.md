# Impeccable design context

This file gives the impeccable design skills the project context they need to
avoid generic output. It currently captures the link/navigation standard we set
deliberately; the broader sections are starter stubs — run `/impeccable teach`
to flesh them out through the full discovery interview.

## Design Context

### Users
Primarily internal staff and facilitators of A Window Between Worlds (AWBW), a
nonprofit, working in data-dense admin screens (events, registrations,
scholarships, payments, allocations), plus public-facing registration and
payment forms used by event attendees.

### Brand Personality
Calm, trustworthy, supportive. The admin UI favors clarity and low cognitive
load over flash; the public forms should feel warm and reassuring.

### Aesthetic Direction
Tailwind utility classes for styling and Font Awesome (free, solid) for icons —
no custom CSS or inline SVG unless necessary. Sentence case for UI labels,
headings, and display text (never title case). Per-domain accent colors come
from `DomainTheme` (events, scholarships, payments, organizations, etc.).

### Design Principles
1. **Sentence case everywhere** — labels, headings, buttons. Use
   `.underscore.humanize`, never `.titleize`, for user-facing text.
2. **Icons must mean one thing** — an icon's job is to disambiguate, so never
   reuse the same glyph for two different behaviors (see link affordances below).
3. **Affordance matches behavior** — what an element looks like it will do must
   be what it does. Don't show a "new window" cue on something that navigates in
   place.
4. **Accessibility is part of the affordance** — visual-only cues (icon, color)
   must be paired with text a screen reader can announce.
5. **Calm density** — these are working screens; prefer muted, consistent
   affordances over loud ones.

### Links & navigation affordances
The behavior of a link must be obvious from how it looks, and each icon means
exactly one thing.

- **Opens in a new browser tab** → use the `new_tab_link` helper
  (`app/helpers/application_helper.rb`). It is the **only** source of the
  `fa-arrow-up-right-from-square` (box-arrow) icon, sets `target="_blank"` +
  `rel="noopener"`, and appends screen-reader-only `(opens in new tab)` text
  (WCAG G201). Never hand-roll this icon inline.
  - `<%= new_tab_link "View receipt", receipt_url, class: "underline" %>`
  - Block form for links with their own leading icon/markup; the box-arrow is
    appended after the content. Pass `icon_class:` to resize/recolor it.
- **Same-tab navigation** (next page, drill-in, jump to a record, breaking out
  of a Turbo frame with `turbo_frame: "_top"`) → **never** use the box-arrow.
  Use a directional arrow (`fa-arrow-right`) to mean "go to", or no icon at all
  (same-tab is the expected default and needs no marker). If the link already
  carries an action icon (e.g. `fa-plus` for "Add"), add no second icon.
- **In-page anchor / scroll within the page** → a down arrow (`↓` /
  `fa-arrow-down`) or no icon. Never the box-arrow.
- **Prefer same-tab.** Don't force a new tab unless there's a real reason
  (e.g. preserving a half-filled form the user would lose). When in doubt,
  navigate in the same tab.
- **Reconcile sizing** — the box-arrow marker defaults to a small inline size in
  the helper; don't sprinkle ad-hoc sizes (`text-[0.55rem]`, `text-[10px]`,
  `w-3 h-3`, …) per call site.
